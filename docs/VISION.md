# Kien vision (strategy, 2026-11-09)

This is strategy, not a product commitment. It records the direction Abdullah set. Nothing here changes the build order in [kb/15](kb/15-roadmap-build-order.md).

## The direction

1. **Help about five audit firms implement Kien.** Partner firms run their own independent testing on Kien. Positioning is premium, not cheapest.
2. **Build our own AI-native audit practice.** Kien Solutions runs its own engagements with hired auditors, using the same workflow.
3. **Expand into about five audit specialties.** Each specialty reuses the workflow core: identity, permissions, engagements, evidence, tasks, approvals, reporting and measurement. Each brings its own methods.

## Ground rules

- A partner firm's data and IP are not Kien's by default (working assumption from Abdullah's direction). Treat them as the firm's, and do not reuse them for another firm or for Kien's own practice without written permission.
- Partner-firm separation (one practice's data never visible to another) is a build requirement. See readiness item 23.
- Humans approve findings and sign reports. Software never does.

## Open conflict (needs advice)

Serving partner firms and running Kien's own practice may compete for the same clients and methods. This is an open question. It needs legal and commercial advice before any decision. Until then, no plan here resolves it.

## What this does not yet cover

- GitHub and Notion vision alignment was never done.
- Pricing and budget are not set.
- Specialty choices are not chosen.
